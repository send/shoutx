# Candidate integration probe

This is an implementation experiment, not a new CLI acceptance policy. The
producer remains unchanged. The candidate recombines the retained full-scalar
leading-mapping and grapheme-boundary evidence from the compatibility notes.
It is not a list of selected languages or a list of observed failures to strip.

The checked-in candidate has 1,105,522 initial scalars in 341 ranges. Its JSON
records input payload/property digests. The existing ASCII and escaped CR/LF
path is retained. Candidate generation uses positive leading-mapping outcomes
and the retained start-boundary classes (Other, L, V, T, LV, LVT and RI), then
intersects the recovered datasets. It does not establish consumer applicability
or change the evidence's conditional nature.

`scripts/test-unicode-policy.py` checks this candidate against the pinned Runner
package under explicit Invariant and en-US cultures. It reuses package download,
hash verification and extraction code, loads the package runtime, and records
current OS-image/runtime/backend identities. The initial matrix uses the four
existing hosted targets; a moving image label is not a historical snapshot.

Each start is tested with two suffixes for mask and warning. Separate cases
check exact Unicode TITLE/FILE values, with and without neighboring typed
metadata. Output contains only aggregate mismatches, not failing input details.
These are parser checks, not actual Worker effects or a proof over all suffixes.
No acquired vendor data is shipped with shoutx. Final implementation needs its
own reproducible table-generation contract and producer/Worker verification.
